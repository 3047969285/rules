# 我的规则体系

## 作用与来源

这套规则用于按任务提供回复、安全、执行、技术、Java/XML 和文档规范。唯一源是当前账号下的私有仓库：

`%USERPROFILE%\codex-personal-rules\rules`

本文件夹是自动同步的阅读副本。`.cursor/rules`、`.agents/skills` 和 `.codex/AGENTS.md` 也是安装副本。云端 clone 中编辑规则；后台任务每 5 分钟自动拉取、安装，并自动推送稳定变更。清单只负责路由，不会自行执行 Hook。

## 最小常驻

Codex 每轮常驻这些短规则：

- 核心优先级和任务分流
- 简体中文及基础回复风格
- 保密与安全底线
- 提问扩写：每句先内置扩成角色、任务、规则、约束、示例、输出、输入，再执行
- 竞争式协同：复杂任务由当前代理自己审查、自己当裁判，拆成细则后再执行；禁止三个模型审批。拿不定先问用户
- 性价比：每天约 7 小时、连续约半个月、三个项目同时跑时，固定 Composer 2.5，不开 Fast。短确认可用 Haiku 5.5

长执行流程、完整人设、质量复核和领域细则均按任务加载。

## 分类触发

- 简单问答、短确认：不加载技能或长分册。
- 只读查看：只加载内容领域需要的规则，不触发执行技能。
- 实际写入、自动化或交付：加载安全执行技能；直接实现才加载 agent-exec-minimal；实际交付再加载质量复核规则。
- 长技术说明、正式计划或交付摘要：加载沟通规则。完整女友风只在用户明确提出时加载。
- 每句提问：先做提问扩写，再决定直接改还是进入竞争式协同。
- 复杂任务：当前代理自己当裁判后再动手，禁止三个模型审批。
- 非平凡方案、调用链或风险审查：加载架构规则。
- Java/XML：只处理真实代码时加载 Java 技能，并按组件和风险读取对应分册。
- DOCX/XLS/XLSX 或模板/源/结果文件：加载文档技能与项目模板规则。
- 规则索引、00-force-all 和完整清单仅用于路由不清或规则维护。

## 分类目录

- 00-总纲与清单：核心、索引、机器清单和低频完整流程
- 01-回复风格与语言：基础回复、兼容语言规则和按需个人风格
- 02-安全与执行：保密底线、直接交付和按需质量复核
- 03-架构与技术说明：复杂方案和技术审查
- 04-Java规范：Java/XML 分册与完整参考
- 05-兼容参考：历史路径和其它参考材料

## 维护原则

- 常驻规则只留所有任务都需要的短约束。
- 详细规则写清触发条件，避免重复抄入全局入口。
- 对外只报告已核对的改动和验证证据，不输出隐藏推理。
- 本仓库为 Private；不得公开仓库或加入含敏感数据的文件。
