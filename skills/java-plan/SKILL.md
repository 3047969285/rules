---
name: java-plan
description: Java 新功能或非极简改动编码前的需求扩写与四方案对比流程，用户说「按规则出方案」「Java 新需求」时使用
---

按 ~/.claude/rules/java.md 与 architecture.md 执行，不写代码，只输出：

1. 需求扩写：背景与目标、功能范围、涉及模块、入参出参、业务规则、非功能要求、约束、前置条件、待确认点。
2. 先读真实代码与配置，再列方案；没读到的写未知。
3. 至少 4 套真实有差异的方案（保守兼容 / 推荐均衡 / 激进重构 / 最小改动或分期）。用户已有倾向时，单列「用户方案 vs 架构师方案」。
4. 每套含：思路与调用链、组件与复用、改动文件、接口设计、Controller→Service→ServiceImpl→Mapper→XML 逐层职责、事务/SQL/索引/并发/安全/回滚、优缺点与适用场景。
   必写两行：`配置改动：无` 或 `配置改动：仅改 application.yml 的 [段名]，原因：[白名单类别]`；`产出物：仅业务代码，无测试/过程文件`。
5. 按复杂度、改动范围、性能、维护性、扩展性、安全、兼容、测试成本横向对比，给推荐与依据。
6. 等用户确认方案后再编码。极简改动或用户说「直接做」时不走本流程。
